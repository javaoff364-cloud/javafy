# Production Deployment

## Supported deployment model

Javafy supports a long-running Node.js server and Vercel Node.js Functions. Static assets and generated pages are emitted to `dist/`; server-rendered pages, API routes, and middleware run through the server runtime.

## Build and start

```sh
npm install
npm run build
npm run build:example
cd examples/hello-world
HOST=0.0.0.0 PORT=3000 node ../../node_modules/javafy/dist/index.js start
```

For your own app, run the CLI from the application root after installing the published Javafy packages and building the app. Keep the server process alive with your process manager or container runtime.

## Environment

| Variable | Meaning | Default |
| --- | --- | --- |
| `HOST` | Bind hostname or IP | `javafy.config.js` `dev.host` |
| `PORT` | TCP port, integer 1–65535 | `javafy.config.js` `dev.port` |

Use `HOST=0.0.0.0` in containers when the platform routes traffic to the container interface. Do not expose development endpoints in production; they are not part of the production server.

## Vercel

New projects created with `javafy create` include `api/index.js` and `vercel.json`. Connect the project to Vercel and deploy with the default configuration. The build command runs `npm run build`; Vercel serves generated files from `dist/` and rewrites unmatched paths to the Javafy Node.js function. This adapter uses the Node.js runtime, not the Edge runtime.

If upgrading an existing project, add the generated `api/index.js` and `vercel.json` files from a fresh Javafy scaffold, then redeploy.

## Static hosting

The generated `dist/` directory contains assets and pre-rendered HTML. Static hosting is suitable only when every required route is generated and no request-time SSR, API route, or middleware execution is needed. Dynamic routes not generated by SSG return 404 unless their `getStaticPaths` configuration uses `fallback: "blocking"`; blocking fallback requires the Node.js production server and is not compatible with static-only hosting.

## Reverse proxies and health checks

Terminate TLS at your trusted platform proxy and forward requests to the Node.js listener. Configure the platform health check to call an application-owned API route such as `/api/health`. Javafy does not create an implicit health endpoint.

## Operational security

- Keep credentials in the hosting provider's secret/environment manager, never in source files or page props.
- Validate and limit request bodies in API handlers; use schemas appropriate to your application.
- Apply authentication, authorization, rate limits, and CSRF protections where relevant.
- Use explicit cache keys for personalized loader data. The cache is per process and is not a shared distributed cache.
- Keep dependencies current and run `npm audit --omit=dev` as part of release review.
- Log detailed errors server-side, but return generic error messages to clients.

## Troubleshooting

- **Port already in use:** choose another `PORT` or stop the process holding the configured port.
- **Permission denied:** use an unprivileged port or adjust the runtime's bind permissions.
- **Missing server manifest:** run the production build before starting the server.
- **A route returns 404:** verify the file-based route path and whether a dynamic path was included by `getStaticPaths`.
- **A static deployment misses dynamic pages:** generate every route at build time or deploy the Node.js server for blocking fallback/SSR.
