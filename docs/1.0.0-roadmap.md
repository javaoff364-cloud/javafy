# Javafy 1.0.0 — Production Readiness Plan

This document records the acceptance scope for Javafy 1.0.0. The implementation
has been merged into `main` after review. npm publication and the public GitHub
Release are separate final distribution steps; neither is implied by the merge.

## Release principles

- Preserve documented 0.9.0 behavior unless a breaking change is explicitly
  documented and justified.
- Prefer Web Platform APIs and keep the runtime Node.js-focused and explicit.
- Never claim support for a runtime, deployment target, or feature that is not
  covered by automated tests.
- Keep secrets and detailed internal exceptions out of browser/API responses.
- Make performance claims reproducible; publish the benchmark environment and
  methodology with results.

## Workstreams and acceptance gates

### 1. Public API and architecture
- Inventory every exported symbol and CLI command.
- Define supported Node.js versions, package entry points, and ESM behavior.
- Validate configuration and route definitions consistently.
- Add API compatibility tests and document intentional breaking changes.

### 2. Routing and navigation
- Cover static, dynamic, required catch-all, optional catch-all, nested layout,
  not-found, loading, and error-boundary behavior.
- Test query/hash transitions, browser history, prefetch, cancellation, and
  rapid navigation races in a browser-like integration environment.
- Ensure navigation failures cannot leave stale loading state or stale content.

### 3. Rendering and hydration
- Verify SSR output and client hydration for representative React trees.
- Detect and document hydration mismatches.
- Verify SSG output for static and dynamic paths, including missing paths.
- Explicitly document unsupported streaming and fallback behavior unless
  implemented and tested in this milestone.

### 4. Data loading and caching
- Test request-scoped loaders, static loaders, cache expiry, cache-key
  isolation, cache bounds, thrown errors, and aborted requests.
- Ensure user-specific data cannot accidentally share a cache entry when the
  application supplies an appropriate key.
- Document process-local cache semantics and multi-instance limitations.

### 5. API routes and middleware security
- Test method handling, HEAD/OPTIONS behavior, malformed requests, thrown
  handlers, middleware ordering, short-circuiting, and duplicate next() calls.
- Verify internal exception details are not returned to clients.
- Review request body handling, path matching, header forwarding, and response
  semantics for security and correctness.

### 6. Development experience and CLI
- Test CLI argument parsing, startup failures, host/port validation, rebuilds,
  HMR recovery, and graceful shutdown.
- Ensure development-only endpoints and overlays are not exposed in production.
- Provide actionable diagnostics without leaking secrets.

### 7. Production performance
- Add repeatable build-size and runtime benchmarks with warm-up, multiple
  samples, environment metadata, and machine-readable output.
- Measure route matching, server rendering, and representative production
  builds before making optimization claims.
- Optimize only where measurements show a meaningful regression or cost.

### 8. Packaging and deployment
- Verify every workspace package's exports, files, dependencies, and version.
- Test installation from a packed package in a clean example application.
- Document supported Node hosting, static hosting constraints, environment
  variables, health checks, and production startup.
- Verify package contents do not include tests, local artifacts, or secrets.

### 9. Documentation and examples
- Reconcile README, changelog, API reference, examples, and actual behavior.
- Remove duplicated or contradictory documentation.
- Provide a complete production deployment walkthrough and troubleshooting
  guide.

## Verification and distribution

The merged 1.0.0 implementation was verified in CI with the Node.js 20, 22,
and 24 matrix, TypeScript project build, unit/integration tests, example
 typecheck/build, production smoke tests, packed-package installation,
benchmark artifact generation, dependency audit, and CodeQL analysis.

Before npm publication, rerun the repository checks after any release-document
or package-metadata edits:

- `npm install`
- `npm run build`
- `npm test`
- `npm run test:packages`
- `npm run test:production`
- `npm run audit`

Publish only the four public workspaces, in dependency order: `@javafy/core`,
`@javafy/router`, `@javafy/server`, then `@javafy/cli`. The private root
workspace is not an npm package. See [RELEASING.md](../RELEASING.md) for the
exact publication and verification procedure.

## Explicitly not promised yet

Streaming SSR, edge/serverless runtime compatibility, database integrations,
and built-in authentication remain outside the 1.0.0 support contract unless
separately implemented, tested, and documented. Dynamic SSG supports the
explicit `false` and `"blocking"` fallback modes.
